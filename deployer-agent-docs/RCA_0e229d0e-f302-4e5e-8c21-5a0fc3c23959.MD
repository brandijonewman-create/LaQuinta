# RCA — `/images/**` returns 404 on production (la-quinta-living / laquintagolflifestyle.com)

## Summary
Production (Next.js `output: 'standalone'`, served directly from the K8s pod on port 3000) 404s every URL under `/images/**` while `/` renders 200. Root cause: the deploy image's runner stage copies `.next/standalone` and `.next/static` but **never copies `public/`** into the standalone runtime. The Node standalone server (`server.js`) therefore has no `public/` sibling directory to serve static assets from. Your standalone-gotcha hypothesis is correct.

## Evidence (production-side, definitive)
1. **Origin 404 (bypasses Cloudflare):** `GET https://la-quinta-living.emergent.host/images/hero/homepage-hero.jpg` → **404** (serves the Next.js 404 HTML), while `GET /` → **200** (and the HTML `<link rel="preload" as="image" href="/images/hero/homepage-hero.jpg">` is present). Because the pod's own emergent.host origin 404s, this is NOT edge caching.
2. **Source has the assets:** the build's source-unzip step lists `/workspace/public/images/hero/homepage-hero.jpg` and all 28 `/workspace/public/images/communities/*.jpg`, plus `public/properties`, `public/downloads`, etc.
3. **The image-assembly gap (smoking gun):** build layers for run `0e229d0e-f302-4e5e-8c21-5a0fc3c23959` show the runner stage in full:
   - `[runner 3/6] COPY --from=builder /app/.next/standalone ./`
   - `[runner 4/6] COPY --from=builder /app/.next/static ./.next/static`
   - `[runner 5/6] COPY entrypoint.sh /app/entrypoint.sh`
   - `[runner 6/6] RUN chmod +x /app/entrypoint.sh`
   There is **no** `COPY --from=builder /app/public ./public`. `yarn build` runs in the builder ([builder 8/8]); Next.js standalone does not copy `public/` into `.next/standalone/`, so nothing carries `public/` into the runtime image.
4. Confirms your Q1/Q2: production runs the standalone Node server (not `yarn dev`), and there is no `public/` next to `server.js`. Preview serves the images (`next dev`/`next start` serves `public/` directly), which is why the bug is hidden there.

## Why I did not auto-fix via a manifest override
This deployment builds on the platform's **stock `next` template** — there is no manifest override in GCS. Adding a Dockerfile override flips the build to load the *entire* manifest set from GCS (`config.yaml`, `entrypoint.sh`, etc.), none of which I have an authoritative copy of for the `next` template. Reconstructing them from memory would risk breaking every future build, so I'm handing the fix to you instead. (I also could not reproduce in the eph sandbox — it failed to boot with an infra `container not found` error — but the production build-layer trace above is conclusive on its own.)

## Recommended fix (source-side, minimal, low-risk) — YOU apply this
The platform copies the whole `.next/standalone` tree into the image (`COPY --from=builder /app/.next/standalone ./`). So if `public/` exists **inside** `.next/standalone/` at build time, it will be carried into the runtime image automatically. Make the build put it there.

Edit `package.json` build script:

```json
"scripts": {
  "build": "next build && cp -r public .next/standalone/public"
}
```

(Optionally also `&& cp -r .next/static .next/standalone/.next/static` to make standalone self-contained; not strictly required since the platform already copies `.next/static` separately.)

Then redeploy. After deploy:
1. Verify at the **origin** first: `curl -I https://la-quinta-living.emergent.host/images/hero/homepage-hero.jpg` → expect `200 image/jpeg`.
2. Then the apex: `curl -I https://laquintagolflifestyle.com/images/hero/homepage-hero.jpg`.
3. If the origin is 200 but the apex still 404s, Cloudflare cached the earlier 404 — purge `/images/*` at the edge (Cloudflare dashboard; I have no Cloudflare tooling). Cloudflare does not cache 404s by default, so this may be unnecessary.

## Alternative (platform-side, if you prefer not to touch source)
Ask the platform team to add `COPY --from=builder /app/public ./public` to the runner stage of the stock `next` template Dockerfile. This is a latent gap affecting any `next` app that uses `output: 'standalone'` + `/public` static assets.
