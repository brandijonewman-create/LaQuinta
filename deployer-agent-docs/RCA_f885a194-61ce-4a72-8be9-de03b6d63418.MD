# RCA — Deploy run f885a194-61ce-4a72-8be9-de03b6d63418 (golfhomes-az)

## Summary
Redeploy failed at the **build_image** step. The Next.js production build (`yarn build`) failed to compile because the identifier **`BLOG_POSTS` is defined multiple times** in several source files. This is a source-code bug, not a manifest, secret, tier, or infra problem.

## Root Cause
Each of the following files both **imports** `BLOG_POSTS` (e.g. `import { BLOG_POSTS } from '@/lib/blog';`) **and** also declares a local `BLOG_POSTS` (e.g. `const BLOG_POSTS = [...]`) in the same module scope. SWC/Next rejects the duplicate top-level binding, so compilation aborts.

Affected files:
- `app/blog/page.js`
- `app/page.js`
- `app/sitemap.js`
- `components/related-content.js`

## Fix (owner: E1 / code)
In each affected file, remove the duplicate `BLOG_POSTS` binding — keep ONE definition:
- If the data should come from the shared module, keep the `import { BLOG_POSTS } from '@/lib/blog';` and delete the local `const/let/var BLOG_POSTS = ...` declaration.
- If the file intentionally defines its own list, remove the import instead (or rename the local to a distinct name).

Then redeploy. This needs a new build (source change → new image); redeploying the same image will not help.
