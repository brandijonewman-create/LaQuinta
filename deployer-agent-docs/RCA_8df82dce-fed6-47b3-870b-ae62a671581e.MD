# RCA — golfhomes-az build_image failure (duplicate `BLOG_POSTS` import)

## Symptom
`build_image` fails during `yarn build` (Next.js SWC) with:
`the name \`BLOG_POSTS\` is defined multiple times` in four files, build exits 1.

## Runs analyzed (all build_image failures)
- `0e177d7b-750f-4b0c-9e49-c3fc02f2a2c0` — Cloud Build `30758780-...`
- `f885a194-61ce-4a72-8be9-de03b6d63418` — Cloud Build `0f586d68-...`
- `8df82dce-fed6-47b3-870b-ae62a671581e` — Cloud Build `21f0b69b-...` (resumed with **force_repull=true**, i.e. a fresh live-/app re-pull + fresh no-cache Cloud Build)

All three used **distinct, freshly-created Cloud Build IDs** and the last re-pulled source. They reproduced the **identical** error. => NOT a stale build cache and NOT a merged/stale object-storage snapshot.

## Root cause (proven by build logs)
`pull_source` copies the **live preview-pod `/app` working tree** (on disk), NOT git HEAD. The on-disk copies of the four files each carry an **extra** `import { BLOG_POSTS } from '@/lib/blog';` prepended at **line 1**, in addition to the legitimate import later in the same file. The SWC frames the builder printed:

- `/app/app/blog/page.js` — dup at **line 1** AND line 6
- `/app/app/page.js` — dup at **line 1** AND line 9
- `/app/app/sitemap.js` — dup at **line 1** AND line 3 (line 2 = `import { SITE, COMMUNITIES, ZIP_PAGES, COMPARISON_PAIRS, GOLF_CLUBS, ARCHITECTS } from '@/lib/data';`)
- `/app/components/related-content.js` — dup at **line 1** AND line 3

Except for the extra line-1 import, every framed line matches your described HEAD exactly. That is why `git show HEAD`, a fresh checkout, and your `/tmp` copy all build clean (exit 0) while the deploy fails: **the duplicate line-1 import exists only in the uncommitted on-disk working tree of `/app`** — the exact bytes `pull_source` zips and the builder compiles. The requested "rebuild from latest working tree, no cache" was performed (force_repull) and still failed, confirming the live `/app` on disk is the dirty source.

## Fix (Code — E1 must apply; I cannot edit source)
In the preview pod's `/app`, delete the duplicate **line 1** `import { BLOG_POSTS } from '@/lib/blog';` from each of these files (keep the single legitimate import that already appears later in each):
- `app/blog/page.js`
- `app/page.js`
- `app/sitemap.js`
- `components/related-content.js`

Edit the files **on disk in `/app`** (not just via git) and save, then redeploy. Verifying with `git show HEAD` is misleading here — compare the actual working-tree files, e.g. `grep -n "from '@/lib/blog'" app/blog/page.js app/page.js app/sitemap.js components/related-content.js` should show exactly ONE match per file before redeploying.

The previous healthy run `bbe7592b` is still the active run; `https://golfhomes-az.emergent.host` continues serving the old version. The new `next.config.js` redirects (`/golf-clubs/<slug>`, `/communities/phoenician`) will ship once the build passes.
